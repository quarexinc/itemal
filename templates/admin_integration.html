Ödeme bildirimi (webhook)

Bir ödeme sağlayıcısı veya kendi ödeme servisin, başarılı ödemeyi bu adrese bildirdiğinde bekleyen bakiye yükleme talebi otomatik onaylanır ve bakiye eklenir. Kullanıcı önce sitede yükleme talebi oluşturur; talebin numarası deposit_id olarak gönderilir.

Durum: {% if secret_set %}Gizli anahtar tanımlı {{ secret_hint }}{% else %}PAYMENT_WEBHOOK_SECRET tanımlı değil, webhook kapalı{% endif %}

Adres: POST {{ base }}/api/webhook/odeme

Gizli anahtar .env dosyasındaki PAYMENT_WEBHOOK_SECRET değeridir; buradan değiştirilemez ve sayfada tam olarak gösterilmez. İmza, ham istek gövdesinin HMAC-SHA256 özetidir (onaltılık) ve X-Signature başlığıyla gönderilir.

body='{"deposit_id": 12, "amount": "250.00", "status": "success", "transaction_id": "TX-98765"}'
sig=$(printf '%s' "$body" | openssl dgst -sha256 -hmac "$PAYMENT_WEBHOOK_SECRET" | awk '{print $2}')

curl -X POST {{ base }}/api/webhook/odeme \
  -H "Content-Type: application/json" \
  -H "X-Signature: $sig" \
  -d "$body"
  • status: success talebi onaylar, failed reddeder.
  • amount talep edilen tutarla birebir eşleşmelidir; eşleşmezse istek reddedilir.
  • transaction_id benzersizdir; aynı bildirim tekrar gelirse ikinci kez bakiye eklenmez.

Satıcı API'si

Satıcılar kendi panellerinden anahtar oluşturur ve stok ile ilan durumunu otomatik yönetir. Tüm uçlar Authorization: Bearer <anahtar> ister; dakikada 120 istek sınırı vardır.

  • GET {{ base }}/api/v1/me profil, bakiye ve satış özeti
  • GET {{ base }}/api/v1/listings ilanlar
  • POST {{ base }}/api/v1/listings/<id>/stock stoğa kod ekler ({"codes": [...]})
  • POST {{ base }}/api/v1/listings/<id>/status ilanı yayına alır veya duraklatır
  • GET {{ base }}/api/v1/orders satışlar ve komisyon bilgisi
